# Unofficial Master main.go Improvement Plan

## 1. Architecture & Structure

* **Dependency Injection (DI):** Global variables like `hub`, `upgrader`, `db`, and `Q` must be removed from the package scope. Initialize them inside `main()` and pass them explicitly to handlers, services, and tickers via constructors.
* **Decouple DB Schema (DDLs):** Move all 14+ inline `CREATE TABLE` and `CREATE INDEX` string constants out of the application entry point. Place them into a dedicated migration directory and manage them via standard tooling (`golang-migrate` or `goose`).
* **Database Package Isolation:** Create a separate `internal/db` package. Expose a unified initialization function `db.New(config) (*sql.DB, *gen.Queries, error)` to handle connections cleanly.
* **Feature Modularization:** Relocate helper utility routines like `loadTokenSymbolMap`, `loadWatchlistSymbols`, and `findStaticDir` into their respective domain layouts (`internal/db` and `internal/server`).
* **DRY Violations:** Consolidate duplicate definitions of `writeJSON` split across `main.go` and `blueprints.go`. Maintain a single, clean generic utility function inside an external shared package.
* **Broker Registry Pattern:** Move the manual broker background lookup loop out of `main()`. Use a clean registry design pattern inside a `ws` or `broker` package to handle dynamic automated stream initialization.

---

## 2. Security & Session Integrity

* **At-Rest Encryption:** Encrypt sensitive broker master details (passwords, secure TOTP seeds, API secrets, and login pins) using AES-256-GCM before writing them to the database.
* **Session Lifecycle Management:** Refactor `service.Sessions` to avoid unbounded memory leak paths. Introduce a robust Time-To-Live (TTL) eviction policy and implement sliding-window refresh token rotation.
* **Brute-Force Mitigation:** Inject rate-limiting middleware (using a token-bucket algorithm per remote IP address) specifically targeting `/api/login`.
* **Explicit CORS Access controls:** Introduce isolated CORS management middleware restricting cross-origin resource requests strictly to targeted application configurations (e.g., `http://localhost:5173`) instead of allowing open `*` catch-alls.
* **User Identity Layer:** Replace hardcoded standalone administrative assertions with a normalized multi-user scheme using salted `bcrypt` hashes.
* **Cryptographic Error Auditing:** Explicitly trap errors returned during session initialization routines from `rand.Read` inside `service/auth.go` to prevent predictable sequence fallback vectors.

---

## 3. Resilience, Concurrency & Error Trapping

* **Context Isolation for Core Execution:** For transactional execution endpoints like order placement, modifications, or cancellations (`/api/broker-modify-order`), separate critical upstream updates from volatile request lifecycle cancellations using `context.WithoutCancel(ctx)`. This prevents orphaned orders if a client drops mid-network execution.
* **Fail-Safe Goroutine Guards:** Wrap all high-concurrency loops and websocket background handlers in defensive defer-recovery middleware (`recover()`). A single pipeline panic in an isolated broker thread must never take down the entire algo runtime.
* **Resilient Stream Reconnectors:** Embed stateful Exponential Backoff Reconnection loops inside the system websocket broker layers to autonomously recover connection sequences when institutional streams experience micro-drops.
* **Explicit SQL Processing Checks:** Eliminate all silent execution drops by systematically validating return values across `db.Exec` runs.
* **Eradicate Terminal Panics:** Eliminate application-level `log.Fatalf` inside boot loaders. Bubble errors gracefully up to `main()` so the runtime can safely close ongoing tracking loops before exiting.
* **Structured Stream Scanning:** Guarantee that scanner data processing loops (`rows.Scan`) explicitly capture and route formatting failures directly into the core application logging pipeline.

---

## 4. Database Layer Optimizations

* **SQLite High-Concurrency Tuning (WAL Mode):** Since the runtime tracks high-velocity ticker footprints concurrently with trading calculations, prevent standard database locking bugs (`database is locked`) by explicitly initiating **Write-Ahead Logging (WAL)** on initialization:
    ```go
    db.Exec("PRAGMA journal_mode=WAL;")
    db.Exec("PRAGMA synchronous=NORMAL;")
    ```
* **State Migration Integrity:** Replace inline boot routines running `ALTER TABLE` and `DELETE FROM master_contracts` with isolated database schema tracking scripts execution.
* **Subquery Purging:** Deprecate expensive linear runtime scans (`DELETE FROM master_contracts WHERE id NOT IN (...)`) executed during boot cycles.
* **Timezone Synchronization:** Standardize all timestamp tracking fields to use strict UTC boundaries (`datetime('now')`) instead of regional definitions (`localtime`) to avoid execution skew across cloud instances.
* **Lazy-Loaded Cache Layers:** Replace full table table memory maps during boot processes with localized, smart In-Memory caches (such as synchronized map states). Load master schemas dynamically or restrict caching exclusively to active tracklists and open positions.
* **Unified Query Interfaces:** Migrate raw structural query blocks into clean execution schemas mapped inside production-ready `sqlc` models (`gen.Queries`).

---

## 5. Clean Code Quality & Observability

* **Thin Main Architecture:** Shrink the structural logic inside `main()` by outsourcing initialization blocks into an explicit server config construct engine: `server.New(cfg)`.
* **Mockable Boundaries:** Establish core execution interfaces across database layers to facilitate unit testing with mock data layers without depending on concrete hardware database setups.
* **Import Optimization:** Purge redundant `fmt` and `encoding/json` declarations out of `main.go`. Maintain strict separation of parsing concerns across localized handlers.
* **Local TLS Layer Setup:** Provide structural support for HTTPS configurations within local execution environments if routing targets extend beyond standard local loopback environments.
* **Structured Log Streaming:** Replace basic `log.Printf` logging commands with high-speed structured logging pipelines using Go's built-in `slog` engine or standard libraries like `zap`. Ensure all metrics streams pass along structured tracing contexts.
* **Platform Probes:** Expose reliable diagnostic paths (`/healthz` and `/readyz`) to allow external balancers or management layers to verify system health.
* **SPA Route Fallback Routing:** Ensure all SPA asset lookups fall back gracefully to the primary router root instead of throwing basic 404 errors when a user refreshes deep path structures (like `/settings` or `/watchlist`).
